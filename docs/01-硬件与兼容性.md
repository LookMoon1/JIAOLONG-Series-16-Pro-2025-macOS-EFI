# 硬件与兼容性

## 机器

| 项 | 值 |
|---|---|
| 型号 | MECHREVO JIAOLONG 系列（蛟龙 16 Pro 潮玩版，Series-X6FR55xx） |
| 平台 | AMD（AMI BIOS `N.1.15MRO19`），无 Above 4G Decoding / Resizable BAR 选项 |
| CPU | AMD Ryzen 9 9955HX（Granite Ridge / Zen5，16C/32T） |
| 独显 | NVIDIA RTX 5060 Laptop `10DE:2D19` |
| 核显 | AMD Radeon 610M `1002:13C0` |
| 内屏 | NE160QDM-NZL，2560×1600 eDP，**MUX 直连独显** |
| 内存 | 32 GB DDR5（≥16 GB 即可） |
| 存储 | NVMe SSD，单盘 GPT（容量不限，系统分区 ≥100 GB 为宜） |
| 无线 | MediaTek MT7922 Wi-Fi 6E `14C3:7922` |
| 蓝牙 | MediaTek Bluetooth（MT7922 的 USB 半部，ID 因机型而异） |
| 有线 | Motorcomm YT6801 `1F0A:6801` |
| 声卡 | Senary SN6140 `14F1:1F87`（HDA 控制器 `1022:15E3`） |

> **保留原则**：凡是"型号 / 设备 ID"（CPU、GPU `10DE:2D19`、网卡 `14C3:7922`、
> 屏幕 `NE160QDM-NZL`、BIOS 版本）都保留 —— 别人靠这些判断自己的机器是否适用。
> 凡是"我这台机器的数据"（序列号、MAC、三码、**分区容量**、磁盘序列号）一律不记录。

### 关键有利条件

**内屏 MUX 直连独显**。这意味着 NVIDIA 驱动可以直接点亮内屏，不需要核显兜底 ——
这是这台机器能跑 macOS 的根本前提。若你的机器是 Optimus / 混合输出，本 EFI 不适用。

## 分区布局

典型布局是**单盘双系统**：

```
p1 EFI
p2 MSR
p3 Windows (C:)
p4 Recovery
p5 数据盘 (D:)
p6 macOS (APFS)  ← 装在这里
```

> ⚠️ **本文不记录任何真实容量** —— 每台机器都不一样，照抄没有意义。
> 动手前请自己用 `diskutil list`（macOS）/ `Get-Partition`（Windows）确认。
>
> **单盘双系统**：安装时只能对预留的那段空闲空间操作。**绝不能**在磁盘工具里选中物理磁盘点「抹掉」，
> 那会抹掉整个 Windows 盘。正确做法是选中物理磁盘 → 点「分区」→「+」新建 → 拖到目标大小 → APFS。
>
> **判断依据用文件系统类型（APFS），不要靠容量猜。**

## 兼容性总表

### 完全可用

| 功能 | 实现 |
|---|---|
| **内置硬盘引导** | **BIOS `Hard Drive BBS Priorities`**（无需 U 盘，见 [07](07-内置EFI引导修复.md)） |
| 系统启动 | OpenCore DBG-109 + 本 EFI |
| 显卡加速 / Metal | NullMoth NVIDIA 3.0（NVRM / NVAccel / NVRMFB / NVRMAGDC） |
| 内建键盘 | PS/2 → VoodooPS2Controller |
| 触控板 | I2C HID（`UNIW0001`）→ VoodooI2C + VoodooI2CHID |
| **Wi-Fi** | **MT7922 原生 → YYavicWiFi 0.8.0** |
| **内置声卡** | **VoodooHDA 3.7.1 BL 版**（扬声器 / 耳机孔 / 麦克风，见 [08](08-内置声卡修复.md)） |
| 亮度调节 | NullMoth `nvrmacpibl=1`（**仅控制中心滑块**） |
| USB | USBToolBox + UTBDefault |
| Windows 双启动 | OC 菜单自动列出 Windows Boot Manager |
| 关机 / 重启 | 正常 |

### 部分可用 / 未验证

| 功能 | 状态 | 备注 |
|---|---|---|
| 睡眠 / 唤醒 | ⚠️ 未系统验证 | 建议先测一次再作日常使用 |
| 蓝牙 | ⚠️ **可正确连接设备，但未验证可用性** | 能配对连接，尚未验证音频/传输是否正常，见下 |
| 内屏分辨率 | ⚠️ | 2560×1600 面板，只有 **1280×800（2×）** 是真正清晰的 HiDPI 模式；中间档位为非 HiDPI 缩放 |

### 🔴 已知缺陷：Fn 键

| 操作 | 结果 |
|---|---|
| 单独按 **Fn** | ❌ 无任何反应 |
| **Fn + F 功能区按键** | 🔴 **系统直接重启** |
| 单独按 F1–F12 | ✅ 正常（作为普通功能键） |

**未修复。日常使用请避开 Fn 组合键；调亮度用控制中心滑块。**
详细现象、已排除项与排查命令见
[docs/02-关键配置与踩坑.md](02-关键配置与踩坑.md) 第四节之二。

### 不可用

| 功能 | 原因 | 可行替代 |
|---|---|---|
| 有线网口 | Motorcomm YT6801 无 macOS 驱动 | **RTL8153 USB 网卡**（免驱，推荐） |
| 电池百分比 | `SSDT-EC` 隐藏真实 EC（`BAT0` 是 `EC0` 的子设备）；移除 SSDT-EC 会导致启动卡死 | 无 |
| HDMI/DP 音频 | NVIDIA `NHDA`（`pci10de,22eb`）未驱动 | 未研究，与扬声器修复互不影响 |

### 关于内置蓝牙

MT7922 的蓝牙半部是一个**独立的 USB 设备**。macOS 原生没有为它准备的通用传输层路径，
本 EFI 用 `BlueToolFixup.kext` 的 patch 加上 `SimpleMtkBtFw.kext` 的固件加载来打通。

> 具体 USB ID 因整机厂商的模块封装而异（同一颗 MT7922 可能报不同 ID）。
> 先查你自己的：`system_profiler SPUSBDataType | grep -A5 -i bluetooth`

**实测状态：系统能识别蓝牙并正常完成设备配对/连接。**

> ⚠️ 但"连上了"不等于"能用"——蓝牙音频（A2DP）、文件传输、Handoff/Continuity
> **均尚未验证**。若你依赖蓝牙音频，建议先实测，或直接用 USB 蓝牙适配器（已验证可用）。

排查命令：

```bash
system_profiler SPBluetoothDataType      # 看 Chipset / Transport / State
ioreg -l | grep yyavic-bt                # 看驱动做了什么（SimpleMtkBtFw 侧）
log show --last 5m --predicate 'process == "bluetoothd"' | grep -i "Transport is set"
```

> 参考（YYavicWiFi README）：macOS 26 上 BlueToolFixup 的原生 patch 会把非 Broadcom 设备
> 导向通用 USB 路径，从而**切断** `bluetoothd` 里的 MediaTek 路径。上游提供了
> `setup-bluetooth.sh` 或一条 `Kernel > Patch` 来把那个字节改回来。**本项目未采用该 patch**，
> 当前蓝牙可用性来自 `BlueToolFixup` + `SimpleMtkBtFw` 的组合。

## 与同配置成功案例的对照

| 项目 | 硬件 | 与本机关系 |
|---|---|---|
| [ASUS TX Gaming 7Pro](https://github.com/VisualTechStudio/ASUS-TX-Gaming-7Pro-Ryzen-CN-OpenCore-EFI) | **9955HX + RTX 5060 Laptop** | **CPU 与独显完全相同**，`ExitBootServicesDelay=3000` 的来源 |
| [gqm321 macos15-rtx5070-jiaolong](https://github.com/gqm321/macos15-rtx5070-jiaolong) | 7845HX + RTX 5070 Laptop | **同机型**（蛟龙），MUX 独显直连 |

> **重要**：这两份参考的 SMBIOS 选择**相反** —— TX7 用 `MacBookPro16,2`，gqm321 用 `MacPro7,1`。
> 本 EFI 采用 `MacBookPro16,2`，因为 TX7 与本机 **CPU + 独显完全一致**，参考价值更高。
> 教训：**同配置的完整 EFI 比"同平台"的更有价值**；判断机型限制前必须读 issue 评论，不能只看标题。
