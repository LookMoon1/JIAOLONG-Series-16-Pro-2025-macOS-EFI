# 内置声卡修复（macOS 26 Tahoe 无声）

> **状态：已修复并验证（2026-11-18）**
> 内置扬声器、3.5mm 耳机孔、麦克风均可用。

---

## 一、故障现象

- 系统设置 → 声音 里**没有任何输出设备**
- 扬声器、耳机孔均无声
- `system_profiler SPAudioDataType` 的 Devices 列表**为空**

---

## 二、根本原因（硬件没坏）

### 核心原因：macOS 26 删除了 AppleHDA

> **苹果从 macOS 26 (Tahoe) 起移除了系统声卡驱动 `AppleHDA.kext`。**
> Tahoe 仍支持的 Intel 机型全部走 T2 芯片音频，苹果不再维护 AppleHDA。

**连锁后果**：

```text
AppleHDA 被移除
    ↓
AppleALC.kext 失去宿主（它是 AppleHDA 的补丁/插件）
    ↓
所有基于 AppleALC 的黑苹果声卡方案在 macOS 26 上彻底失效
```

> 这解释了一个重要的事实：**2026-11-15 尝试的 AppleALC + SimpleHDA（layout-id 15）失败，
> 与当时的配置操作无关** —— 是路线本身在 macOS 26 上就不成立。

### 硬件是好的

```text
AMD Azalia 控制器  pci1022,15e3
ACPI 设备名        AZAL
PCI 路径           PciRoot(0x0)/Pci(0x8,0x1)/Pci(0x0,0x6)
```

在 `ioreg` 设备树里清晰可见，**只是没有驱动去认领它**。

### 解决思路

改用**不依赖 AppleHDA** 的独立声卡驱动：**VoodooHDA**。

---

## 三、已执行的修复

### 1. 下载正确的版本

**VoodooHDA 3.7.1 BL 版**（BootLoader 注入版）

- 来源：官方仓库 [CloverHackyColor/VoodooHDA](https://github.com/CloverHackyColor/VoodooHDA)
- commit `d9e642d`（2026-10-23 构建）

> ⚠️ **必须用 BL 版**。稳定版 3.6.8 依赖外部 `IOAudioFamily`，
> 而它不在启动内核集合里，从 Big Sur 起直接 EFI 注入会报 **`Invalid Parameter`**。

### 2. 修改 IONameMatch（关键）

`VoodooHDA_BL.kext/Contents/Info.plist` → `IOKitPersonalities → VoodooHDA → IONameMatch`

```text
原值：  "HDAS"
改为：  ["AZAL", "pci1022,15e3"]
```

**为什么**：只匹配本机声卡，**不碰 NVIDIA HDMI 声卡（NHDA）**，避免冲突。

### 3. 放置驱动

复制到两份 EFI 的 `OC/Kexts/VoodooHDA_BL.kext`：

- 内置硬盘 EFI
- U 盘 1401 的 EFI

**内容完全一致，MD5 已校验。**

### 4. 注册到 config

两份 `config.plist → Kernel → Add` 各新增一条，**紧跟 `Lilu.kext` 之后**：

```xml
<dict>
    <key>BundlePath</key>    <string>VoodooHDA_BL.kext</string>
    <key>ExecutablePath</key><string>Contents/MacOS/VoodooHDA_BL</string>
    <key>PlistPath</key>     <string>Contents/Info.plist</string>
    <key>Enabled</key>       <true/>
</dict>
```

**其余原有条目一律未动**；SIP、boot-args、ACPI 均未改动。

### 5. 一个重要的排查插曲

> **12:34 的发现**：本机当时实际**一直从 U 盘 EFI 引导** ——
> 所有 OpenCore 启动日志都写在 **U 盘根目录**，内置 EFI 从未产生日志。
>
> 第一次修复只改了内置 EFI，所以 11:45 重启后驱动没加载、依旧无声。
> 后来把修复同步到 U 盘 EFI，才真正生效。

**教训**：改 EFI 前先确认**你实际从哪份 EFI 引导**（看 OC 日志写在哪个分区）。

## 四、验证方法

### 重启后应看到

系统设置 → 声音 → 输出，出现 VoodooHDA 的输出设备。

本机实测识别的端口：

| 类型 | 端口名 | 对应 |
|---|---|---|
| 输出 | `Speaker (Analog)` | 内置扬声器 |
| 输出 | `Headphones (Green Right)` | 机身 3.5mm 耳机孔 |
| 输入 | `Microphone (Analog)` / `Microphone (Pink Right)` | 两路麦克风 |

> `Green` / `Pink` 是 VoodooHDA 按 PC 音频颜色惯例生成的通用端口名，**正常现象**。
> codec 显示 `Unknown` 也正常 —— 只是 VoodooHDA 未收录具体型号名，不影响使用。

### 命令行验证

```bash
# 驱动是否加载
kextstat | grep -i voodoo
ioreg -n AZAL -r -l | grep -i voodoo

# 看引导日志确认注入
# 在 U 盘根目录/内置 EFI 根目录找最新 opencore-*.txt，搜索 VoodooHDA
# 应看到：Prelinked injection VoodooHDA_BL.kext - Success
```

## 五、使用提示

> ⚠️ **VoodooHDA 不会自动切换输出**（不像原生 macOS 那样插耳机就切）。

- 插 3.5mm 耳机后，到 **系统设置 → 声音 → 输出** 手动选 `Headphones`
- 拔耳机要外放，再切回 `Speaker`
- 连着蓝牙耳机时会优先走蓝牙输出，测试有线端口前先在输出列表里选定

## 六、重启后仍有问题怎么调

### 1. 确认驱动挂上了

```bash
kextstat | grep -i voodoo
```

无输出 = 没挂上，检查 `EFI/OC/Kexts/VoodooHDA_BL.kext` 是否存在、config 条目是否在。

### 2. 用 getdump 查 codec 详情

```bash
cd tools目录
./getdump > ~/Desktop/getdump.txt
```

可确定 Realtek 具体型号（如 ALC269 / ALC256 / ALC245）和扬声器对应引脚。

### 3. 安装设置面板调参

```bash
sudo cp -R VoodooHDA.prefPane /Library/PreferencePanes/
```

到系统设置中打开 VoodooHDA 面板：
- 输出选对设备，把 PCM / iMix 滑块拉高
- 麦克风有设备但收不到声音：选中麦克风，IMix 与 Speaker 拉到最大
- 音量调节异常可尝试 `VoodooHDAEnableVolumeChangeFix`

### 4. 手动指定布局（笔记本常见）

若自动引脚配置不对，可注入布局号：

```xml
config.plist → DeviceProperties → Add
路径：PciRoot(0x0)/Pci(0x8,0x1)/Pci(0x0,0x6)
属性：voodoo-layout-id = Data，值如 0f000000（十六进制小端，示例=布局15）
```

布局号到 AppleALC 仓库 `Resources/<codec型号>/` 目录查，逐个尝试最接近的。
每改一次需重启一次。

## 七、回滚

### 方法 A（还能进 macOS）

```bash
cp "/Volumes/EFI/EFI/OC/config.plist.backup-pre-voodoohda-20261118-105918" \
   "/Volumes/EFI/EFI/OC/config.plist"
rm -rf "/Volumes/EFI/EFI/OC/Kexts/VoodooHDA_BL.kext"
```

重启即恢复。

### 方法 B（进不了 macOS）

重启进 Windows，挂载 EFI 分区后覆盖 config、删除 kext 文件夹。
或用 OpenCore 菜单里的 OpenShell 完成。

> 回滚只撤销本次声卡驱动，**不影响其他配置、数据和系统设置**。

| 方案 | 说明 |
|---|---|
| VoodooHDA 3.6.8 走系统扩展 | 解压官方 `VoodooHDA.kext-368.zip`，同样改 `IONameMatch=AZAL`，`sudo cp -R` 到 `/Library/Extensions/` 后 `sudo kmutil install --update-all` |

## 九、风险说明

- VoodooHDA 3.7.1 是官方仓库的 **alpha 构建**
- 其内嵌 `IOAudioFamily` 的 EFI 注入方式已在 **Tahoe 26.7.1 + OpenCore 1.0.7 + 全开 SIP** 环境验证通过 —— 本机环境与之接近
- 音频核心代码成熟（源自 FreeBSD `snd_hda`）
- **最坏情况只是无声或不加载**，回滚即可，不影响数据与系统
- 驱动只匹配 `AZAL`，**不会接管 NVIDIA 或其他设备**
- 未修改 SIP、boot-args、DSDT/SSDT、系统分区
- 小版本更新一般无需重做；若更新后无声，先确认驱动是否仍加载

## 十一、给其他人的重要提醒

> **如果你在 macOS 26 上没声音，不要再尝试 AppleALC 了。**

网上的教程绝大多数写于 macOS 15 及更早，那时 AppleHDA 还在。
在 Tahoe 上：

- ❌ AppleALC + `alcid=15` → **不会工作**
- ❌ 各种 `layout-id` 试错 → **不会工作**
- ✅ **VoodooHDA BL 版** → 可用
- ✅ **USB 声卡** → 最省心

这是 macOS 26 带来的**架构性变化**，不是配置问题。
