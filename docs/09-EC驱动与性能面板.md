# EC 驱动与性能面板

> **状态：已在实机运行（2026-11-19）**
> 只读 EC 采样驱动 + 性能面板 App + 桌面组件。
> 源码在 [`panel/`](../panel/)，本文记录**技术背景与与 EFI 的集成**。

---

## 一、为什么需要这套东西

机械革命在 Windows 下有官方控制中心（MGIC），能看温度、切性能档、调风扇。
macOS 下没有对应软件。

**目标**：在 macOS 上看到和 MGIC 类似的信息。

**约束**：**只读**。不写寄存器、不接管风扇、不切换档位。

---

## 二、为什么不能移植 MGIC

机器是 **Uniwill（同方 / 志奥）** 方案。整机 ACPI 里：

| 事实 | 影响 |
|---|---|
| `INOU0000` 提供 `ECRR` / `ECRW` 两个方法，读写的是 **`0xFED50000` eSPI 共享内存窗口** | **不是**传统 EC 端口 `0x62` / `0x66`，通用 EC 驱动（如 `ECEnabler`）读不到 |
| `EC0`（`PNP0C09`）是真正的 EC，但 macOS 侧只有 VirtualSMC 模拟的读法 | 强行读实存**曾导致开不了机** |
| SMC 里没有任何风扇键（`F0Ac` 等） | 第三方风扇控制方案（如 `SMCAMDProcessor`）无接口可用 |
| 没有 `AMDRyzenCPUPowerManagement` / `SMCAMDProcessor` | 无法用现成方案读 AMD 传感器 |

**结论**：MGIC 的 Windows 驱动栈（WMI + EC 私有命令）**无法整套搬过来**。

**可行路线**：自建只读通道。

```text
EC 共享内存窗口 0xFED50000
        ↓  MechrevoEC.kext 每 1.5 秒只读采样（通过 ACPI ECRR 方法）
IORegistry 属性（FanMap / MidMap / HighMap / IPCMap / Seq / Failures）
        ↓
面板 App / 桌面组件（纯读取展示）
```

## 三、驱动设计要点

| 项 | 值 |
|---|---|
| Bundle ID | `com.local.MechrevoEC` |
| 匹配设备 | `IONameMatch = INOU0000`，`IOProviderClass = IOACPIPlatformDevice` |
| 采样周期 | 1500 ms |
| 数据源 | ACPI `\_SB.INOU.ECRR(addr)`（**只读**） |
| 发布属性 | `FanMap` / `MidMap` / `HighMap` / `IPCMap` / `Seq` / `ReadOK` / `Failures` / `ProbeOK` |

### 采样区间

| 属性 | 地址范围 | 内容 |
|---|---|---|
| `FanMap` | `0x0D0`–`0x0DF` | 风扇占空比 / 档位 |
| `MidMap` | `0x430`–`0x4AF` | 温度 / 风扇表 / 功率 |
| `HighMap` | `0x700`–`0x7FF` | 电量 / 功耗墙 / 性能字段 |
| `IPCMap` | `0xEA0`–`0xECF` | OEM IPC 命令块 |

### 安全设计

- **完全不调用 `ECRW`**，不写任何寄存器
- 单字节读取之间插 **1ms 延时**（`IOSleep`），避免把 EC 打爆
- 每轮 448 次读取约 0.45 秒，周期 1.5 秒，不会持续占用

## 四、已破解的寄存器语义

**全部经现场实测对拍，不是猜的。**

| 地址 | 含义 | 实测证据 |
|---|---|---|
| `0x461` | **当前性能档位**（持久，按键切换才变） | 100 / 126 / 200 三点与用户操作逐一对应 |
| `0x469` | 档位镜像值（与 `0x461` 恒等） | 同步变化 |
| `0x449` | **CPU 温度（℃）** | 空闲 47 → 满载 56 → 回落 49；切办公 52 → 38 |
| `0x44F` | **GPU 温度（℃）**（DSDT 命名 `VGAT`） | 恒 79–82；本机 5060 无电源管理，空闲也高 |
| `0xD8` | 风扇档位（0–7） | 换档随动，负载下 1 → 6 |
| `0x43E` | 温度限值（**恒定值**） | 全程 91–92，不随负载变化 |

### 档位映射

| `0x461` 值 | 档位 |
|---|---|
| 100 | 办公 |
| 126 | 均衡 |
| 200 | 狂暴 |

**按键循环顺序**：均衡（126）→ 办公（100）→ 狂暴（200）

> Windows 下是 办公 → 均衡 → 狂暴，**macOS 下前两档对调**。
> 这是 EC 固件行为，与软件无关。

## 五、与 EFI 的集成

### 需要改动的地方

| 位置 | 改动 |
|---|---|
| `EFI/OC/Kexts/MechrevoEC.kext` | **两份 EFI 都要放** |
| `config.plist → Kernel → Add` | 末尾追加一条 |

```xml
<dict>
    <key>Arch</key><string>Any</string>
    <key>BundlePath</key><string>MechrevoEC.kext</string>
    <key>Comment</key><string>Mechrevo EC read-only sampler</string>
    <key>Enabled</key><true/>
    <key>ExecutablePath</key><string>Contents/MacOS/MechrevoEC</string>
    <key>MaxKernel</key><string></string>
    <key>MinKernel</key><string></string>
    <key>PlistPath</key><string>Contents/Info.plist</string>
</dict>
```

### 验证

```bash
ioreg -c MechrevoEC -r -d 1 | grep -E "ProbeOK|Failures|Seq"
```

期望：`ProbeOK = Yes`、`Failures = 0`、`Seq` 每 1.5 秒递增。

## 六、🔴 事故记录：自定义 SSDT 导致开不了机

> **这是本项目最严重的一次事故，必须记录。**

### 发生了什么

2026-11-19，为读取 EC 真实 RAM（`XHPP` 权威温度、`PL1L`/`PL2L` 功耗墙），
新增了 `SSDT-MechrevoData.aml`，与改版驱动 **v7** 同时启用。

**结果：macOS 完全无法启动。**

### 修复过程

进 Windows，挂载 EFI，把相关项改回禁用状态：

```powershell
mountvol S: /S
# 然后文本编辑器改 S:\EFI\OC\config.plist
```

备份文件（EFI 内保留）：
- `config.plist.bak-before-mechrevo-20261119-100307`
- `config.plist.bak-before-ecram`
- `config.plist.bak-win-20261119-032312`（Windows 侧原始干净版）

### 当前状态

| 项 | 状态 |
|---|---|
| `MechrevoEC.kext` | ✅ **已启用**（v9 只读采样） |
| `SSDT-MechrevoData.aml` | ❌ **`Enabled=False`**（文件保留，不启用） |

> **元凶未定位** —— 无法确定是 SSDT 还是 v7 驱动导致，或两者组合。
> 既然当前组合（v9 驱动 + SSDT 禁用）稳定，**不要再改动**。

### 教训

1. **不要一次性启用多个未验证项** —— 出了问题无法二分定位
2. **改 EFI 前必须备份**，且备份要能被 Windows 访问（U 盘 EFI 天然满足）
3. **`config.plist` 只能用文本编辑** —— PowerShell 的 `[xml]` 会把 `<true/>`
   写成非法的 `<true>false</true>`，OpenCore 直接解析失败

## 七、已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | **没有风扇 RPM** | 窗口寄存器内无转速字段（已排查 `0x000`–`0xFFF` 与 `0x1800`–`0x18FF`），只显示档位 `0xD8` |
| 2 | **CPU 温度偏低** | `0x449` 是 EC 侧采样，满载仅 56℃（真实 85℃+）。**只看趋势** |
| 3 | **GPU 空闲 80℃ 是真实的** | 5060 在 macOS 下无电源管理，空闲也在高频 |
| 4 | **软件不能切档** | 档位由 EC 固件处理物理键，OS 侧无入口 |

### 软件切档的三条路线结论

| 路线 | 结论 |
|---|---|
| ① 盲写窗口寄存器 | ❌ **不做** —— 找不到干净写入位点，盲写可能锁死风扇、黑屏 |
| ② 模拟物理按键 | ❌ **不通** —— 内置键盘走 PS/2，该键由 EC 固件处理，**不上报 OS** |
| ③ 复刻 MGIC 命令协议 | ⚠️ 唯一可行方向，需 Windows 侧抓包对比 |

> 💡 当前做法：**档位只用物理键切换，软件不写寄存器。**

## 九、面板显示内容

- 性能档位徽章（办公 / 均衡 / 狂暴）
- CPU 负载、内存占用
- CPU / GPU 温度
- 风扇档位
- GPU 利用率、显存占用
- CPU 温度趋势（近 2 分钟）
- 电量与供电状态
- 驱动采样状态（`Seq` / `Failures`）

桌面组件是同样的数据，但贴在桌面图层：不占 Dock、可拖动、右键退出。
